# CSV processing checkpoint — 2026-10-06

`process-csv-order` is a server-only Supabase Edge Function. POST JSON `{ "order_id": "UUID" }` using the project's service-role bearer token from a trusted server only. Never put that token in a browser, repository, or customer message. Both gateway JWT validation and exact server-key comparison are enabled.

Only `spreadsheet-cleanup` orders with status `paid`, a payment confirmation timestamp, and a CSV file are eligible. An atomic status update claims the order; concurrent/repeated requests cannot process the same paid state twice. No payment flags are created or altered by this function.

The processor handles UTF-8 comma-delimited files up to 2 MB, trims surrounding whitespace, removes fully blank rows, preserves numeric strings and duplicate rows, normalizes quoting/newlines, and rejects ambiguous columns/quotes. Formula-like values are flagged and remain private pending review. Output is written under `results/` in the existing private `order-files` bucket; the original upload is preserved. Output location and QA counts are recorded in `orders.result_text` as JSON. Completion auto-delivers only deterministic CSV results with **zero formula-like cells and zero duplicate rows**: status becomes `delivered`, `result_checked=true`, and a delivery timestamp is set. Results with any formula-like cell or duplicate row remain private with status `needs_review` and `result_checked=false`. Source files and raw results remain in the private storage bucket.

Errors also hold claimed orders for review. If a database outage prevents this update, the order may remain `processing` and requires operator recovery. An uploaded result may remain private but unreferenced if the final database update fails. Webhook delivery retries re-attempt dispatch while an order remains paid. Orders already processing or held for review require operator recovery; no external notification is configured.

Tests: `node --test processor.test.mjs`. Tests exercise data preservation, malformed input, payment/auth gates, state transitions and replay with mocked Supabase HTTP responses. Deployment is separately checked for rejection of anonymous requests. A real paid-order end-to-end run remains pending Whop credentials. The payment webhook invokes this function after payment validation, and retries dispatch on duplicate authenticated success events; broader PDF/XLSX processing and outbound delivery notifications remain unfinished. Customer downloads use confirmed email, order ownership, approved delivery status and short-lived signed URLs.

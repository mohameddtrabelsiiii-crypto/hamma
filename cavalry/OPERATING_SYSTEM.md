# Cavalry Operating System

## Mission
Build revenue-producing digital services with $0 incremental software spend.

## Rules
- Never fabricate customers, payments, credentials, results, reviews, employers, companies, dates or numbers.
- Never bypass identity, payment, CAPTCHA, platform or account verification.
- Prefer free infrastructure and open-source tooling.
- Automate qualification, delivery, QA and reporting where technically possible.
- Escalate only when an external service requires an owner action or legally binding authorization.

## Customer acquisition
Use only legitimate public outreach and marketplaces that permit automation. Never spam or impersonate.

## Offer ladder
1. Spreadsheet/document cleanup
2. Research packs
3. Workflow automation design
4. Business-document transformation

## Delivery
Intake -> scope -> price -> payment confirmation -> process -> QA -> delivery -> request feedback -> measure conversion.

## Fourthwall commerce operations (Med Art)
For the owner's authorized Fourthwall print-on-demand project, **load `cavalry/commerce/README.md` and `cavalry/commerce/store-state.json` before proceeding**. The current business is prelaunch, not a confirmed paying or 24/7 autonomous store. Draft ideas and truthful zero-budget organic experiments live in `cavalry/commerce/growth-sprint.md`.

Hard stop: do not publish or sell with inactive merchant payouts, unverified checkout, unlicensed art, or unknown profit math. When the local authorized Hermes/Fourthwall connection is offline, continue only independent no-cost planning and monitoring and report that live store data could not be checked. The Github state JSON is a dated snapshot, **not** real-time account data. Never store bank data, customer PII, access tokens, cookies or OAuth secrets in GitHub.
